# Care U｜「問卷頁」＆「Loading頁-2」完成版頁面規格

## 1. 文件定位

- 規格狀態：目前完成版
- 規格基準：`CareU_問卷頁_Loading頁-2_原型.html`
- 基準檔 SHA-256：`07e65d2f635ea8fe8d19d351ddc6e553efe249fea80bd8270193bac01f93bb4c`
- 涵蓋範圍：問卷頁、問卷完成確認、Loading頁-2、分析失敗狀態、報告頁 Placeholder、原型 Demo Controller
- 不涵蓋範圍：首頁、Loading頁-1、排除視窗、正式報告內容、登入頁、OCR、AI／RAG、推薦演算法、API、資料庫與正式後端

本 HTML 為可單獨開啟的前端互動原型。字體、背景圖片、Logo 與程式均內嵌於單一檔案，不依賴外部資源載入；LINE Seed TW 的授權來源註記保留於 HTML。

## 2. 核心體驗原則

- 品牌感受：專業、溫和、省心、清楚、個人化。
- 呈現方式：混合式單步問卷；一個頁面處理一個主題，相關性高的子題可同頁並列。
- 已從體檢資料取得的題目不再顯示。
- 問卷頁只蒐集資料，不提供疾病診斷、醫療結論、用藥指示或健康效果保證。
- Loading頁-2 以階段文案表達進度，不顯示無法保證準確的百分比。
- 原型完成流程為：問卷 → 完成確認 → Loading頁-2 → 報告頁 Placeholder。

| 用途 | 色彩 |

### 3.2 字體

- 主字體：LINE Seed TW，於 HTML 內嵌並命名為 `CareU LINE Seed TW`。
- 備援順序：LINE Seed TW → Noto Sans TC → PingFang TC → Microsoft JhengHei → system-ui → sans-serif。
- 僅內嵌實際使用的 Regular 400 與 Bold 700，避免下載未使用字重。
- 關閉瀏覽器模擬字重：`font-synthesis: none`。
- 400：本文、說明、小標、一般選項與輸入內容。
- 700：主標、頁面標籤、按鈕、Loading 狀態、重要操作文字。

### 3.3 容器與背景

- 全頁最小高度使用 `100svh`。
- 背景由白至淺灰漸層、淺藍與暖橘／珊瑚柔光、資料點 Canvas 及淡化網絡圖層組成。
- 問卷卡最大寬度 900px，半透明白底、34px 圓角、淡藍邊框、柔和陰影及背景模糊。
- Loading 卡最大寬度 680px；錯誤卡最大寬度 580px；報告 Placeholder 最大寬度 760px。

## 4. 入口模式

### 4.1 完整問卷模式（無健檢資料）

- HTML 預設載入此模式。
- 頁首標籤：健康問卷。
- 主標：先從幾個日常問題開始。
- 說明：沒有體檢資料也沒關係，我們會從你的生活習慣與健康狀況開始了解。
- 由問卷蒐集基本資料，之後進入生活習慣、測量資料、過敏與條件式安全資訊。

### 4.2 資料補充模式（已有健檢資料）

- 頁首標籤：資料補充。
- 主標：我們已讀取你提供的體檢資料。
- 說明：接下來只需要補充幾項資訊，幫助我們更完整地了解你的日常狀況。
- 不顯示已從健檢資料取得的基本資料題。
- 原型內以假資料模擬既有資料；正式版應由前一流程或後端提供缺漏題目清單與既有狀態。

## 5. 問卷內容與順序

### 5.1 完整問卷模式

| 固定進度槽 | 頁面／主題 | 題型與內容 | 必填規則 |
| --- | --- | --- | --- |
| 1 | 先提供幾項基本資料 | 年齡數值、生理性別單選、體重數值 | 三項皆需完成 |
| 2 | 每日蔬果攝取是否充足？ | 單選：充足／不足／不確定 | 必選一項 |
| 3 | 每週中高強度活動總時數？ | 單選：150 分鐘以上／75～150 分鐘／少於 75 分鐘／幾乎不動 | 必選一項 |
| 4 | 近一個月主觀睡眠品質如何？ | 單選：很好／尚可／不好／很差 | 必選一項 |
| 5 | 補充目前知道的身體測量資料 | 腰圍；居家血壓的收縮壓與舒張壓 | 每組可輸入數值或選「目前不知道」 |
| 6 | 是否對下列任一項目有已知過敏反應？ | 多選；含「其他」及「無已知過敏」 | 至少選一項；選其他時需填文字 |
| 7 | 最後確認兩項安全資訊 | 是否懷孕、是否正在哺乳 | 僅生理性別為女性時顯示；兩題皆必答 |
| 8 | 問卷填寫完成 | 完成確認與送出 | 按「送出問卷」後才進入 Loading頁-2 |

完整問卷的進度以八個固定槽位計算。若安全資訊頁因條件不符而略過，完成頁仍對應第八槽，避免因選擇生理性別而重新計算總長度或讓進度倒退。

### 5.2 資料補充模式

| 固定進度槽 | 頁面／主題 | 與完整模式的差異 |
| --- | --- | --- |
| 1 | 每日蔬果攝取 | 相同 |
| 2 | 每週活動 | 相同 |
| 3 | 睡眠品質 | 相同 |
| 4 | 身體測量資料 | 僅詢問腰圍，不顯示居家血壓 |
| 5 | 已知過敏 | 相同 |
| 6 | 安全資訊 | 顯示懷孕與哺乳兩項 |
| 7 | 問卷填寫完成 | 送出後進入 Loading頁-2 |

### 5.3 過敏多選項目

牛奶及乳製品、大豆及其製品、芝麻、黑豆、魚類及其製品、含麩質穀物、乳糖不耐、真菌類（如菇蕈類）、花生／堅果、其他、無已知過敏。

- 選擇「無已知過敏」時，取消其他已選項目。
- 選擇任一具體項目時，取消「無已知過敏」。
- 只有選擇「其他」時才顯示「其他已知過敏」文字欄。
- 取消「其他」時隱藏文字欄並清除其值。
- 多選更新只修改目前控制項與答案狀態，不重新繪製整頁，因此不出現閃爍。

## 6. 表單元件與排版規則

- 主題標題位於題目區上方，相關子題置於各自的淺灰白框內。
- 基本資料桌面版採三欄：年齡／生理性別／體重；三個子題框的高度與控制項內距對齊。
- 生理性別、是／否及「目前不知道」使用圓角選取按鈕；文字及選項置於框內，不跨壓框線。
- 數值欄（年齡、體重、腰圍、血壓）控制高度為 44px，垂直內距 8px，與選取按鈕視覺高度一致。
- 測量資料桌面版可並列腰圍及居家血壓；血壓內含收縮壓、舒張壓兩欄。
- 安全資訊桌面版以兩個同規格子題框並列；底部留白縮減，與其他選取類型一致。
- 一般單選／多選桌面版採兩欄，Mobile 改為單欄。
- 按鈕最小高度 50px；上一題為次要按鈕，下一步／送出為品牌藍主按鈕。

## 7. 操作與驗證

- 第一頁「上一題」停用；其餘頁面可返回並保留答案。
- 未完成當前必填內容時，「下一步」停用。
- 若以程式或特殊操作觸發未完成送出，顯示：「請完成這個步驟，或選擇『目前不知道』。」並將焦點移到第一個可輸入欄位。
- 選擇測量項目的「目前不知道」時，立即清除同組數值。
- 「目前不知道」已選取時，焦點進入同組任一數值欄便自動取消該狀態，可直接輸入，不需先手動取消。
- 更改生理性別後重新計算實際顯示頁，但進度仍使用固定槽位。
- 題目切換後焦點移到新頁主題標題，方便鍵盤與輔助科技使用者掌握內容更新。

## 8. 進度規則

- 僅顯示進度條，不顯示「步驟 x / x」或百分比文字。
- 軌道為淺藍灰，填色使用品牌橘 `#FB8F54`。
- 進度依目前頁面所對應的固定槽位更新，轉場時間 0.35 秒。
- 完整模式固定八槽；資料補充模式固定七槽。
- 條件頁顯示或略過不會重設總題數，不會造成進度條因性別選擇而縮短、倒退或跳回。

## 9. 答案保存

- 原型使用 `sessionStorage`，鍵名為 `careu-questionnaire`。
- 保存內容：模式、答案及目前頁面索引。
- 同一分頁重新整理時可恢復同模式的填答進度。
- 不使用帳號、資料庫或正式後端。
- Demo「重新開始」會清除目前原型保存狀態。
- 正式版應以後端／session 接手，並另行訂定敏感健康資料的保存、傳輸、權限與刪除政策。

## 10. 完成確認頁

- 標題：問卷填寫完成。
- 說明分兩行：
  - 已完成目前所有題目。
  - 確認送出後，將整合資料並準備個人化報告。
- 此頁仍保留上一題，可返回修改答案。
- 主按鈕文字改為「送出問卷」。
- 點擊後顯示短暫「正在送出」狀態，約 0.45 秒後進入 Loading頁-2。

## 11. Loading頁-2

### 11.1 功能定位

Loading頁-2 代表整合問卷與既有資料、分析身體資訊、整理保健方向及準備報告。它不再處理檔案讀取、上傳內容判斷或補充問卷建立。

### 11.2 正常狀態與節奏

| 階段 | 文案 | 原型時間 |
| --- | --- | ---: |
| 1 | 正在整理你提供的資料…… | 1.6 秒 |
| 2 | 正在理解你的身體訊息…… | 1.8 秒 |
| 3 | 正在整理適合你的保健方向…… | 1.8 秒 |
| 4 | 正在準備你的個人化報告…… | 1.2 秒 |
| 完成 | 報告準備完成 | 約 0.65 秒轉入報告 Placeholder |

總示範時間約 7.05 秒，屬固定計時的前端模擬；正式版應由後端狀態驅動。

### 11.3 視覺與動畫

- 沿用 Care U 背景與 Logo。
- Logo 橘色圓點以柔和上下跳動呈現。
- 狀態以對話框顯示，文字採 700 字重。
- 三個點依序跳動；文案切換採淡出、輕微下移與淡入。
- 底部固定顯示：「請保持頁面開啟，完成後將自動進入報告頁。」並納入 Safe Area。
- Loading頁-2 全區文字禁止反白。
- 不使用 Spinner、旋轉圓圈或假百分比。

## 12. 分析失敗狀態

- Demo 可模擬在前兩個 Loading 階段後失敗。
- 錯誤卡及標題置中。
- 標題：這次分析沒有順利完成。
- 說明：可能是網路或系統暫時忙碌。你的問卷內容已保留，可以再試一次。
- 操作：
  - 返回問卷：回到目前模式並保留答案。
  - 再試一次：重新執行正常 Loading 流程。
- 此狀態代表網路、API 或系統處理失敗，與 Loading頁-1 的上傳檔案排除狀態不同。

## 13. 報告頁銜接

- Loading 完成後淡入報告頁 Placeholder。
- 顯示完成勾號、`REPORT READY`、標題「你的個人化報告已準備完成」。
- 說明此處將進入正式報告頁；本完成版不設計正式報告內容。

## 14. Demo Controller

右下角可收合 Demo 面板只供原型展示，不屬於正式使用者介面。提供五項操作：

1. 資料補充模式。
2. 完整問卷模式。
3. 直接開啟 Loading頁-2。
4. 模擬分析失敗。
5. 重新開始。

正式上線前應移除或由開發環境旗標控制。

## 15. Responsive

### 15.1 Desktop

- 問卷卡維持最大 900px 閱讀寬度。
- 一般選項兩欄；基本資料三欄；測量及安全資訊兩欄。
- 內容依視窗寬度使用 `clamp()` 調整字級、外距與卡片內距。

### 15.2 Mobile（650px 以下）

- 頁面左右留白 18px，問卷卡內距 18px、圓角 25px。
- 選項、基本資料、血壓欄及其他欄位全部改為單欄。
- 上一題／下一步按鈕平分可用寬度。
- Demo 控制靠右下並避開 Safe Area。
- Loading 底部提示避開裝置底部安全區。

## 16. Accessibility

- 文件語系為 `zh-Hant`。
- 問卷畫面、Loading 畫面及報告畫面以標題建立 `aria-labelledby` 關聯。
- 單選使用原生 radio；多選使用原生 checkbox；群組使用 `radiogroup`／`group` 與標籤關聯。
- 狀態文字使用 `aria-live="polite"`；驗證訊息使用 `role="alert"` 與 `aria-live="assertive"`。
- 題目切換後將焦點置於主題標題；錯誤狀態出現後將焦點置於錯誤卡。
- 鍵盤焦點使用可見的品牌藍外框。
- 已選取狀態同時使用邊框、背景、標記／勾號，不只依靠顏色。
- `prefers-reduced-motion: reduce` 時大幅縮短動畫、停止 Logo 跳動並保留文字狀態更新。

## 17. 動畫規則

- 畫面切換：淡入淡出及最多 8px 的輕微垂直位移。
- 題目切換：約 0.38 秒淡入。
- 選項 Hover：最多 1px 上移；選取時不重新繪製整頁。
- Loading Logo：1.45 秒循環的柔和跳動。
- Typing dots：1.2 秒循環、每點錯開 100ms。
- 不使用大幅滑動、彈跳、旋轉式 Loading、強烈縮放或過度遊戲化效果。

## 18. 原型技術邊界與後續接手事項

- 本檔為單頁、單檔、純 HTML／CSS／JavaScript 原型，未連接任何後端。
- 健檢資料、缺漏題目與分析結果均為 Demo 邏輯；不可視為真實醫療處理。
- 正式實作需將固定題目與條件邏輯改為後端回傳或正式問卷設定。
- 正式 Loading 應依伺服器狀態推進，並處理逾時、重試、離線與重複送出。
- 正式送出需定義 API、驗證、錯誤碼、防重送、資料加密與健康資料隱私政策。
- 使用了 `:has()`、`backdrop-filter`、`100svh`、Safe Area 及較新的 JavaScript 語法，正式支援範圍以現代瀏覽器為主；上線前應依目標裝置執行相容性測試。

## 19. 完成版判定

本規格與基準 HTML 共同構成目前「問卷頁」＆「Loading頁-2」完成版。後續修改應以本檔 SHA-256 或原始附件識別基準版本，先更新 HTML，再同步更新本規格中的流程、題目、文案、驗證、時間與元件規則。
