# Care U｜報告頁與會員登入視窗：完成版頁面規格

- 定稿日期：2026-09-27（臺灣時間）
- 狀態：目前介面原型完成版；後續修改以此版本為基準。
- 完成版 HTML 存檔名稱：`CareU_報告頁_會員登入視窗_原型.html`。
- 本規格依據：本次確認的最新版 HTML，原檔名為 `CareU_報告頁_會員登入視窗_互動原型.html`；改名不涉及頁面內容修改。
- 適用範圍：報告頁、共用會員登入／註冊／忘記密碼視窗、組合選擇與購買示範、Loading 完成轉場。
- 文件用途：供組員理解畫面與互動，並作為正式開發的交接基準。描述現有原型，不將歷次已取消的設計列為需求。

## 1. 頁面定位與流程

Care U 以「專業、省心、個人化」為核心，協助使用者從身體資料與問卷紀錄，了解值得優先關注的保健方向，再比較相關品項與調整組合。

頁面承接「問卷送出 → Loading 頁-2 → 報告」。原型提供 Loading 的完成轉場，不重新執行問卷、檔案解析或 AI 分析。

閱讀與操作順序：

1. 看見報告標題與個人化摘要。
2. 查看身體優先關注方向圖表。
3. 展開重點保健方向，了解分析依據與提醒。
4. 登入後查看可比較的保健品項。
5. 調整專屬保健組合，核對月組合摘要。
6. 開啟確認購買視窗，完成模擬選購。

此版為單一可開啟的 HTML，CSS、JavaScript、資料、字體與主要視覺素材均內嵌。沒有正式會員驗證、醫療判讀、支付或訂單後端。

## 4. 身體優先關注方向圖表

- 標題：「先看看，你的身體優先關注方向」。
- 說明：「依目前提供的資料，整理值得優先了解的保健方向。」
- 橫條顯示排名、分類名稱、相對長度與分數。
- 原型最多顯示本次結果前 8 項；不足 8 項時只顯示已有項目。
- 不提供「查看全部項目」功能。
- 不顯示底部 `0 25 50 75 100` 刻度，也不顯示「保健優先關注方向」「關注優先度 0–100」「Priority Score」文字方塊。
- 前三名使用暖橘淡漸層，其餘使用藍色淡漸層。

### 4.1 互動

點選公開項目後，在圖表下方顯示該方向的名稱、優先度、摘要與分數提醒；再點相同項目可收合。只重播本次點選橫條的動畫，不重播所有項目。

### 4.2 分數說明

「分數，代表關注順序」放在圖表區內的提醒方塊，不放側欄。標題垂直置中，不附登入鍵。內容為：

> 數值越高，代表依目前資料排在較優先關注的位置。不是健康狀態分數，也不代表疾病風險、實際健康程度或醫療上的補充必要性。

不另顯示「點選公開項目，查看相關說明」。

## 5. 重點保健方向與就醫提醒

### 5.1 方向卡片

- 區域標題固定為「重點保健方向」。
- 顯示本次結果前 5 項；使用可展開的卡片。
- 收合時顯示排名、方向名稱、短摘要、優先度及展開箭頭。
- 優先度標籤文字使用「優先度」，不使用「關注優先度」。
- 優先度方框規格一致，文字靠近數字；標籤略往下微調，與數字視覺置中。
- 展開後呈現方向摘要、資料依據、原因說明及必要提醒。

### 5.2 警示狀態

| 狀態 | 收合卡片 | 展開內容 |
| --- | --- | --- |
| 接近提醒門檻 | 標題右側黃色三角驚嘆號 | 提醒名稱、說明、來源及示範標記 |
| 就醫警告 | 標題右側紅色圓形驚嘆號，略往上校正 | 提醒名稱、說明、來源及示範標記 |
| 無提醒 | 不顯示警示圖示 | 一般分析內容 |

收合時不顯示「接近提醒門檻（示範）」「就醫警告（示範）」小字，圖示保留可讀取的無障礙標籤。

就醫提醒獨立於保健優先度。原型只接受預設警示資料，未設定真實危險值或接近危險值的數值門檻，也不以優先度分數觸發提醒。正式判定規則需另外定義並由後端提供。

## 6. 未登入與登入後的內容差異

| 區域 | 未登入 | 登入後 |
| --- | --- | --- |
| 報告摘要 | 公開版摘要 | 完整分析摘要 |
| 圖表前兩名 | 顯示排名與「登入會員查看」，隱藏分類、真實分數及真實橫條長度 | 顯示完整內容 |
| 重點方向前兩名 | 鎖定卡片與登入入口，不呈現個別就醫提示 | 顯示方向、分析依據與適用提醒 |
| 第三名以後 | 顯示公開分析；有提醒時依公開卡片呈現 | 顯示完整分析 |
| 推薦區 | 中央會員預覽與登入 CTA，不另加「會員專屬」標籤 | 顯示可推薦方向與候選品項 |
| 下方組合 | 不呈現品項操作區 | 可選擇、更換、移除及確認購買 |

**未解鎖的前兩名若有就醫示警，個別圖示與提醒內容皆不呈現。** 通用健康提醒仍保留。此條為目前完成版行為，取代先前「顯示遮蔽項目的提醒」設計。

HTML 內含完整示範資料，前端隱藏只是展示行為。正式系統必須以伺服器權限決定回傳內容，不能只靠前端遮蔽保護會員資料。

## 7. 為你準備的專屬保健組合

### 7.1 推薦方向卡片

只列出前五大方向中已列入推薦且有候選品項的方向。每張卡包含方向標題、短摘要、「查看分析依據」、候選選項列、目前查看品項，以及該品項的詳細資訊。

無法推薦或資料不足的方向集中於區域下方說明，不為每個方向製作空白推薦品項卡。

### 7.2 選項列的最新定稿

- 所有選項置於同一列，寬度平均分配。
- 品名字級 **12px**、行高 **1.7**；狀態文字 **10px**、行高 **1.6**。這是還原到品名字級放大前的最新設定。
- 「目前組合品項」或「候選品項」與品名放在同一列。
- 不顯示「正在查看」。
- 正在查看的選項採淡橘底與淡橘邊框。
- 長品名保持單行，空間不足時以省略號收尾；選項保留完整品名提示，下方詳卡顯示完整品名。
- 720px 以下，每格至少約 220px，必要時水平捲動；只有一個選項時填滿可用寬度。

### 7.3 查看與加入分開

點選上方選項，只改變目前查看的品項。使用者須按右側「換入組合」或「加入組合」才更新組合。

已選入的品項顯示「已加入組合」，外形參照操作按鈕，改用柔和灰藍配色區分。更新後同步反映於下方組合與金額。

### 7.4 品項詳細資訊

「功效宣稱、證據與品項注意事項」使用可展開區塊，與所屬品項放在同一張卡中。內容包含：

- 來源記載的主要成分。
- 證據類型與該方向的來源宣稱。
- 警語與注意事項。
- 核准字號、核准日期、申請商及來源記載狀態。
- 資料集來源與證據解讀提醒。

此區展開後不重複顯示品名。上方推薦區的詳細資訊維持原有間距，不套用下方候選卡加大的上方間距。

## 8. 你的專屬保健組合

### 8.1 橫式品項卡片

- 顯示方向名稱、單顆膠囊／錠劑示意、品名、推薦理由、30 粒總價、單粒價格與操作。
- 左圖右文，圖片保持正常比例，約為寬高比 `1 / 1.1`；桌面圖寬約 148px，較窄畫面縮小。
- 品名比價格更醒目：桌面品名約 16px、價格約 14px，小螢幕依比例縮小。
- 「主要成分」不單列於下方組合卡的主要資訊區，只放入展開資訊。
- 推薦理由由資料背景連結到可了解的補充成分，例如依飲食紀錄介紹膳食纖維的補充選項；避免只複述「攝取較少」，也不直接認定一定需要補充。
- 「更換品項」位於右側，不獨占一整列；移除使用叉叉並提供完整無障礙名稱。
- 詳細資訊仍屬於同一張品項卡，展開後不再重複品名。

### 8.2 更換品項

1. 點擊「更換品項」展開同方向候選卡。
2. 按鈕變為「收合選擇」，右側箭頭同步翻轉。
3. 候選卡採與目前組合品項相同的左圖右文排版，包含品名、推薦理由與價格。
4. `NT$ 150／30 粒` 等總價及單位保持同一列。
5. 候選卡右側提供「加入」按鈕；目前已選品項顯示停用的「已加入」。不以點擊整張卡直接更換。
6. 加入後同步更新上、下兩區與總價，收合該方向候選區。

「功效宣稱、證據與品項注意事項」的收合標題靠右；候選卡上方留適度間距，收合狀態不保留大塊內容空白。展開內文有左右內距，避免貼齊卡邊。

「更換品項」與「收合選擇」維持一致、已恢復的按鈕內距。相同品項若已被其他方向選入，不重複加入。

### 8.3 空狀態

- 移除單一品項後，保留方向與「尚未選擇品項」「選擇品項」入口，可重新加入。
- 全部清空時，摘要顯示沒有已選品項、總額為零，加入購物車按鈕停用。
- 若本次所有候選品項皆被排除，顯示暫不提供組合，並引導查看上方整合原因。

### 8.4 劑型示意

每張圖只有一顆膠囊或一顆錠劑，不使用瓶罐。以 CSS 製作，依品名與資料索引切換形狀、顏色；不代表實際商品外觀或精確劑型辨識。上方推薦詳卡、下方組合卡及候選卡沿用相同視覺系統。

## 9. 月組合摘要與確認購買

### 9.1 價格呈現

| 位置 | 顯示內容 |
| --- | --- |
| 品項卡總價 | `NT$ 150／30 粒`，金額依品項而異 |
| 品項卡單價 | `NT$ 5／粒` |
| 月組合摘要／購買核對清單 | 品名、單價 × 30 粒、各項金額與總額 |

- 每項固定 30 粒作為訂購數量示範，不提供數量增減操作。
- 不在品項卡重複顯示「× 30 粒・模擬價格」「月組合包・本品 30 粒」。
- 不顯示「月組合包・每項 30 粒」標籤，摘要標題使用「月組合摘要」。
- 原型依原價格換算低額單粒價格並限制在 NT$ 3–12；不是正式售價。
- 30 粒用於展示月組合購買概念，不等同每日建議量，也不保證實際可服用一個月。

### 9.2 摘要卡與流程

摘要採深藍底與淺色文字，桌面位於組合右側並可固定跟隨，窄螢幕改為直向排列。清單以精簡列式呈現，不再堆疊大型商品卡。

按「將組合加入購物車」→ 開啟「確認購買」視窗 → 核對品項、數量與合計 → 按「確認購買」→ 顯示「選購結果（示範）」。

此流程只更新記憶體中的模擬購物車，不扣款、不建立訂單、不處理寄送資訊。空購物車有獨立提示。頁面重新載入後不保留操作狀態。

## 10. 推薦限制與四位示範使用者

候選數量與整份組合品項數是不同概念：一個方向可以只有 1 或 2 款可選，整份組合也可能只有 1 項、3 項、4 項或完全沒有品項。

| 使用者 | 資料情境 | 預設組合 | 主要展示內容 |
| --- | --- | --- | --- |
| 小安 | 健檢＋問卷 | 3 項 | 抗疲勞方向限制 2 款候選；部分過敏資訊待核對；第三名黃色提醒 |
| 小晴 | 健檢＋問卷 | 1 項 | 輔助調節血壓僅 1 款候選，展示單選項與單品項組合 |
| 阿哲 | 健檢＋問卷 | 4 項 | 較完整組合；第一名紅色提醒、第三名黃色提醒 |
| 小柔 | 僅問卷 | 0 項 | 孕期、過敏、用藥等預設排除情境，本次候選品項全數不符合條件 |

不推薦的方向集中說明，例如「部分方向暫不加入組合」或「本次候選品項皆未符合使用條件」，並可展開各方向原因。

「沒有組合」可能是本次候選清單剛好全部不適用，不代表所有保健食品都不能使用。原型排除結果為預設情境，尚未實作逐項比對禁用條件、交互作用或個人適用性的引擎。

右下角 Demo 控制可切換使用者、回到未登入、開啟登入／註冊、前往組合、重設／清空組合及重播轉場。切換使用者會重設組合與購物車，保留目前登入狀態。此控制為展示工具，正式版應移除或限開發環境使用。

## 11. 會員登入視窗

### 11.1 開啟入口與外觀

報告右上角、鎖定圖表、完整報告解鎖、推薦預覽及未登入購物車入口均可開啟共用登入視窗，不離開報告頁。

- 背景遮罩搭配模糊效果，中央白色圓角卡片。
- 包含 Care U Logo、標題、短說明、登入／註冊切換與表單。
- 登入按鈕為完全圓角。
- 密碼欄內右側使用眼睛圖示切換顯示／隱藏，不另顯示「顯示」文字。
- 以較緊湊間距避免一般畫面出現內部捲軸；低高度時隱藏部分非必要裝飾與說明。
- 現有實作仍保留外層可捲動能力並隱藏其捲軸，以支援內容超高的情形；不以截斷表單達成無捲軸外觀。

### 11.2 三種模式

| 模式 | 標題 | 欄位 | 主要按鈕 |
| --- | --- | --- | --- |
| 登入 | 歡迎回到 Care U | 電子郵件、密碼 | 登入 |
| 註冊 | 開始你的保健探索 | 電子郵件、密碼、確認密碼 | 建立帳號並登入 |
| 忘記密碼 | 忘記密碼了嗎？ | 電子郵件 | 預覽重設密碼 |

登入與註冊另提供「使用示範帳號體驗」。表單檢查電子郵件格式、密碼至少 8 字元、註冊密碼一致；錯誤訊息置於表單內，焦點移至錯誤欄位。

忘記密碼僅演示送出結果，不寄信。登入／註冊也不送出或儲存電子郵件與密碼；介面保留「請勿輸入真實密碼」提醒。

### 11.3 成功與關閉

- 登入成功後關閉視窗、解鎖報告與品項操作，保留閱讀位置並適當恢復焦點。
- 點右上叉叉、遮罩或按 Escape 可關閉。
- 開啟時鎖住背景捲動，背景不可操作；Tab 焦點限制於視窗內。
- 切換會員模式會清除密碼、恢復密碼隱藏狀態。
- 登出後回到未登入畫面並清空模擬購物車；原型不建立持久會員工作階段。

## 12. 動畫、頁尾與可用性

### 12.1 Loading 完成轉場

預設先顯示短暫 Loading 展示，接著橘點停止、「報告準備完成」、Loading 淡出、報告淡入。程式預設展示等待約 1100ms，完成提示停留約 650ms，淡入淡出約 550ms；此為完成段展示，不是真實分析進度。

網址加 `?entry=direct` 可直接進入報告。Demo 可重播，不修改既有問卷 HTML。

### 12.2 動態與鍵盤

- 卡片捲入視野時漸入，Logo 光點緩慢懸浮。
- 支援 `prefers-reduced-motion`，減少或取消轉場與動畫。
- 保留可見焦點、跳至分析內容連結、表單標籤、展開狀態、即時訊息區及模態焦點管理。
- 圖示按鈕提供操作名稱，裝飾圖像不增加朗讀負擔。

### 12.3 頁尾

沿用首頁 footer 風格，包含版權／字體資訊及「隱私權政策」「資料來源」「使用條款」「健康資訊聲明」。目前連結只顯示原型提示，正式內容與路由待串接。

分類名稱沿用資料集。來源的 `evidence_score` 沒有用於本頁排序或個人化配對。核准資訊顯示來源記載，未即時查核。

### 13.2 共用介面

| 介面 | 用途 |
| --- | --- |
| `CareUAuth.open({ mode, returnFocus, onSuccess })` | 開啟指定會員模式，設定返回焦點與成功回呼 |
| `CareUAuth.close()` | 關閉會員視窗 |
| `CareUAuth.getState()` | 取得示範會員狀態 |
| `CareUAuth.logout()` | 回到未登入狀態 |
| `CareUTransition.complete(options)` | 接受既有 Loading、報告、狀態文字與橘點元素，執行完成轉場 |
| `CareUReport.loadReport(reportData)` | 載入分析結果並重新呈現 |
| `CareUReport.getSelection()` | 取得已選品項、每項數量 30、單位、單價、品項總價及合計 |
| `CareUReport.replayEntry()` | 重播報告進入轉場 |

事件包含 `careu:auth-change`、`careu:auth-success`、`careu:report-ready` 與 `careu:cart-change`。其中 `careu:cart-change` 在確認模擬購買後發出，不是每次更換品項都發出。

### 13.3 報告資料欄位

| 欄位 | 內容 |
| --- | --- |
| `id`、`name`、`source` | 報告／示範使用者識別與資料背景 |
| `summaryPublic`、`summaryMember` | 未登入與登入後摘要 |
| `results[]` | `categoryId`、0–100 的 `score`、`summary`、`evidence[]`、`reason` |
| `results[].evidence[]` | `label` 與 `value` |
| `results[].alert` | 選填：`level`（`urgent`／`near`）、`label`、`message`、`source`、`demo` |
| `productDirections[]` | 可提供品項的方向 ID，須屬前五名方向 |
| `withheld` | 以方向 ID 對應未提供品項的原因 |
| `candidateLimits` | 選填：每方向展示候選上限，原型接受 1–3 |
| `exclusionSummary` | 選填：整合排除說明的 `title`、`text`、`demo` |

`loadReport` 接受最多 12 筆結果，檢查分類、重複 ID、分數範圍、必要陣列與警示格式，並依分數由高至低排序。這是介面資料檢查，不是醫療規則驗證。候選品項與來源內容仍由內嵌 catalog 提供，正式整合需另行替換。

### 13.4 正式開發尚待接入

- 會員登入、註冊、重設密碼服務與後端權限。
- 使用者真實報告、分析結果與候選品項資料來源。
- 經確認的就醫提醒門檻、禁用條件比對及併用風險檢查。
- 正式價格、訂購數量、購物車、支付與訂單流程。
- 隱私政策、資料來源、使用條款及健康資訊聲明頁面。
- 正式版本移除 Demo 控制及相應示範標記；正式資料就緒前不可將預設資料包裝為真實分析。
