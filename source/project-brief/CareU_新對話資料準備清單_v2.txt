────────────────────────────
四、素材與檔案版本原則
────────────────────────────

1. 只把「最新完成版」當主要 Source of Truth。
2. 舊版若要保留，移到 archive。
3. 同名多版本要說明哪個最新。
4. HTML 若引用外部 SVG / PNG / WebP / CSS / JS，最好把你手上有的檔案一起提供。
5. 缺失素材先標 MISSING，不要自行重新生成。
6. 正式 Logo / 標準字以最新 VIS 為準。
7. Prototype-generated 素材若最終 HTML 有使用，可保留。
8. 假商品圖、假價格、假分析內容要標示 MOCK_ONLY。
9. 不確定是否使用的素材，可先暫存，Phase 1 Asset Inventory 再決定。
10. 不要求分享 font files；記錄字體名稱與使用方式即可。

────────────────────────────
五、新對話第一步不要做什麼
────────────────────────────

不要：
- 立刻建立 Vue App
- 立刻把 HTML 轉 Vue
- 立刻重構全部頁面
- 立刻接後端
- 自行修改正式文案
- 自行改品牌
- 自行整理掉原始資料欄位
- 自行覆寫 Raw Dataset
- 直接把 Derived Dataset 當官方資料
- 直接改原始 Prototype

新對話第一步應該是：

檔案盤點
→ 專案資料夾架構
→ Source of Truth 分類
→ Raw / Derived 分類
→ Brand / Prototype-generated / Mock 素材分類
→ 缺漏確認
→ Git / Source baseline
→ Phase 0 確認
→ 第一個 Agent Preflight

────────────────────────────
七、新對話應如何檢查「資料夠不夠」
────────────────────────────

每個 Phase 開始前，新 Technical PM 必須告訴你：

1. 這個 Phase 現在需要哪些資料？
2. 最低完整度是什麼？
3. 理想完整度是什麼？
4. 你目前提供的檔案是否已達最低需求？
5. 缺少的內容可以：
   - 從現有檔案 Extract Draft？
   - 先標 TBD？
   - 還是會 BLOCKED？
6. 是否先讓 VS Code Agent 進行 Inspect-only Preflight？

只有確認後才進 Implementation。

這樣可以避免：
「資料還不夠 → Agent 卻先修改程式 → 後面才發現要重構」。
